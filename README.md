# 安全生产责任制履职清单考评表 自动生成工具

本仓库基于《安全员安全生产责任制履职清单考评表自动生成工具 v1.1.5》源码，派生出一套**多岗位履职履责工具**：一键把空白模板《XX安全生产责任制履职清单考评表（模板）.doc》生成带当月数据的《XX安全生产责任制履职清单考评表(X月XXX).doc》，图形化录入各岗位考评项（自评/上级评价）、拖拽支撑材料（图片、Word、Excel、PDF 等），由 Microsoft Word 引擎原样填充，输出与手工件版式完全一致。

> **岗位版本**：安全员 v1.1.5 ｜ 班组长 v2.0.1 ｜ 作业长 v3.0.1 ｜ 主要负责人 v4.0.1
> **兼容**：Windows 7 SP1 ~ Windows 11（32 / 64 位） ｜ **运行依赖**：Microsoft Word 2010+（Word 2007 有兼容兜底）

## 快速开始

### 方式 A：直接使用 exe（最终用户，推荐）

1. 将对应岗位的 exe 与模板放在同一目录：
   - 64 位系统：`<岗位>履职考评表生成工具.exe`
   - 32 位系统或不确定位数：`<岗位>履职考评表生成工具_win32.exe`（32 位版在 32/64 位系统均可运行）
   - 模板：对应岗位的「（模板）.doc」
2. 双击 exe 启动，按 [使用说明.md](使用说明.md) 操作即可。

### 方式 B：源码运行（开发环境）

需要 Python 3.8.10（依赖见「开发环境」），进入对应岗位目录执行：

```bash
python generate_kaoping.py
```

## 功能特性

- **岗位化考评项图形化录入**：各岗位按考评表提供「自评描述 / 自评得分 / 材料说明 / 支撑材料 / 评价描述 / 上级评分」，共用一个界面骨架；
- **版式差异自动适配**：
  - 安全员：12 项（①安全绩效20 ②管理体系10 ③~⑩各5 ⑪违章管理20 ⑫其它10）；
  - 班组长：17 项（①安全绩效20 + ②~⑰各5），第 1 项「安全绩效」占 R3+R4 两行、每行独立填写（界面双行输入，20 分拆 10+10，可在 `SUB_ROW_MAX` 调整），合计两行得分一并求和；
  - 作业长：13 项（①安全绩效20 ②~⑧各5 ⑨违章查处20 ⑩~⑫各5 ⑬"六个一"工作实绩10），各考评项 C6~C10 与续行纵向合并，填主行即可；
  - 主要负责人：13 项（①安全绩效20 ②~⑥各5 ⑦违章查处10 ⑧~⑪各5 ⑫"六个一"10 ⑬甲方契合度15），表头无「管理者姓名」栏（考评对象（主要负责人）→评价月份）；
- **支撑材料拖拽**：任意文件，每格最多 15 个；图片显示缩略图，其他文件显示 📄 文件名；双击预览打开源文件、右键删除单个、悬停显示完整文件名；
- **文件夹自动匹配**：拖入当月支撑材料文件夹（或年度根目录，按界面年月自动定位当月子文件夹如 `2026.08`），按各岗位 `material_rules.json` 文件名权重自动匹配、排序填入；
- **考评表读取复用**：选择已生成的考评表(.doc)，自动读取姓名/月份、各考评项**自评描述/自评得分/评价描述/上级评分**与**支撑材料**（图片、Excel、Word 等内嵌文件全部提取还原），回填界面后可直接替换材料、改月份再生成新表；
- **履职履责表评分读取**：选择月度履职履责表(.xlsx)，按对应岗位 sheet（安全员/班组长/作业长/主要负责人月度履职评价表）自动读取姓名与各考评项**评分**，填入「自评得分」（excel 表只提供姓名和分数，不读取"扣分说明"列）；文件含多个姓名时弹出选择框；**xlsx 表头匹配以模板考评项名称为准，已按 2026.07 炼铁保产事业部真实文件对四岗位验证通过**；
- **上级评分/评语自动对应**：某考评项填了自评得分后，「一键生成」时自动生成与之对应的**上级评分（=自评得分）**与**评语（=已完成）**；已手工填写的上级评分/评语不覆盖；未填自评得分的项不生成（版本号不变，四个岗位一致）；
- **一键生成**：后台打开 Word 填充，界面不卡顿，进度条逐项推进，自动计算自评/上级合计，完成后可一键「打开文件 / 打开所在文件夹」；
- **格式保真**：模板只读、生成使用副本；单元格 Range 文本替换保留原格式；图片内嵌并等比缩放（长宽均 ≤ 2cm）；其他文件嵌入为 OLE 对象（图标+文件名，双击打开），失败自动退化为文件名文字；
- **免安装分发**：单 exe + 外置模板即可运行，无需 Python 环境；Win7 纯净系统内置 UCRT，未打补丁也能直接运行。

## 使用方法

详见 [使用说明.md](使用说明.md)。通用流程：顶部填「年份/月份/姓名/命名模板/模板文件/输出目录」，中部逐项录入自评与评价、拖入支撑材料，点右下角「一键生成」。各岗位的考评项清单、模板文件名、命名模板与 xlsx sheet 差异见使用说明「各岗位参数速查表」。

## 配置文件

| 文件 | 作用 | 维护方式 |
|------|------|----------|
| `<岗位目录>\kaoping_config.json` | 记忆输出目录、命名模板 | 程序自动读写，无需手工编辑 |
| `<岗位目录>\material_rules.json` | 各岗位考评项的文件名关键词；**第 1 词权重 2、其余权重 1** | 首次运行自动生成；点「编辑权重」用记事本编辑，保存后重启生效 |
| `<岗位目录>\kaoping.log` | 运行日志（时间/级别/信息） | 程序自动追加 |


## 模板文件

- 模板由甲方提供，程序**只读不写**，生成时使用副本操作，模板原件安全；
- **模板外置、不内置进 exe**，自动定位顺序：
  1. 界面手动选择/拖入的路径；
  2. exe 所在目录（源码运行时为脚本所在目录）；
  3. exe 所在目录的上一级目录。
- 分发 exe 时，请将对应岗位的模板与 exe **放在同一目录**；
- 程序会校验模板结构（期望行×列、表头含「考评对象（岗位名）」「评价月份」），防止模板被换后错格写入；
- 若模板行结构有变，需同步更新对应 `kaoping_core.py` 中的 `ITEM_ROWS` 映射。

## 构建打包

需要 Win7~Win11 兼容构建环境（版本锁定，见「开发环境」）。进入对应岗位目录：

```bash
# 32 位版（32/64 位系统均可运行，老 Win7 首选）——默认
python _build_win7.py

# 64 位版（64 位系统专用）
$env:PYI_BITS="64"; $env:PYI_EXE_NAME="<岗位>履职考评表生成工具"
python _build_win7.py
```

- `_build_win7.py` 调用 PyInstaller 5.13.2 执行对应岗位的 `.spec`；
- spec 将 Win7 运行时整套文件打进 exe（`ucrtbase.dll` + downlevel `api-ms-win-*.dll`），纯净 Win7 免补丁运行；
- `upx=False` 避免杀软误报；构建中间文件在 `%TEMP%`，产物输出到 `dist\`；
- 模板外置、不打包进 exe。

## 自动化测试

无需第三方测试框架，进入对应岗位目录直接运行：

```bash
python tests/test_core.py    # 核心纯函数 + Mock-COM 生成流程：命名/表头替换/合计/行映射/材料匹配/文件夹扫描/xlsx 读取/生成填充顺序
python tests/test_gui.py     # GUI 冒烟：各岗位布局/材料增删/得分校验/异步回填/清空/生成状态
```

> GUI 测试不启动 Word、不弹真实对话框；测试环境需安装 tkinterdnd2。
> `test_core.py` 内含 **Mock Word COM** 用例（`test_generate_doc_fill_sequence`），无需本机 Word 即可验证「表头替换 → 逐项填充 → 合计写入 → 保存」的填充顺序。

**四岗位一致性检查（防漂移）**：四份 `kaoping_core.py` / `generate_kaoping.py` / 测试由「复制改参」派生，最易漏改导致漂移。在仓库根目录运行：

```bash
python check_role_sync.py            # 对比基线，发现新增漂移则退出码 1
python check_role_sync.py --update   # 4 岗位同步修改后刷新基线（首次使用先 --init）
```

## 常见问题

| 问题 | 处理 |
|------|------|
| 提示"找不到模板文件" | 将对应岗位模板放到 exe/程序同目录（或其上一级目录），或点「模板文件-选择」手动指定 |
| 提示"模板表格结构异常" | 模板被替换/改版（各岗位期望行列见「岗位清单与差异」），换回正确模板 |
| 支撑材料自动匹配不准 | 「编辑权重」调整对应岗位 `material_rules.json`（同义关键词一并加入），保存后重启程序生效；未匹配文件手动拖入对应项 |
| 履职履责表读取提示格式变化 | 各岗位月度 xlsx 版式以业务方当月文件为准；**xlsx 表头匹配以模板考评项名称为准，excel 只提供姓名和分数（不读"扣分说明"）**；已用 2026.07（炼铁保产事业部 / 兴达炼铁保产事业部）真实文件验证四岗位可正确读取；若后续表头用词再变，请以模板为准统一或反馈开发者调整 `XLSX_ITEM_KEYWORDS` |
| Word 未安装 | 程序依赖 Microsoft Word，请先安装 |
| 生成时 Word 有弹窗 | 程序已设置 DisplayAlerts=0；首次使用请允许 Word 初始化 |

## 开发环境

Win7~Win11 兼容构建环境（版本已锁定，请勿随意升级）：

```text
Python    3.8.10             # 官方支持 Win7 的最后版本（32 位版可构建 _win32 exe）
pip install -r requirements.txt
```

`requirements.txt` 已锁定全部依赖（pyinstaller==5.13.2、pillow==10.4.0、pywin32==306、tkinterdnd2==0.4.3、openpyxl==3.1.5、olefile==0.47），新环境一条命令即可还原。

> **依赖升级策略（重要）**：Python 3.8 已于 2024-10 停止安全修复，pywin32/pyinstaller 等亦为对应时代旧版——这是为了兼容 Windows 7 SP1 的有意取舍。**一旦业务方确认不再需要 Win7，即可整体升级 Python + 依赖 + PyInstaller**（届时本段删除即可）。

源码一律 UTF-8 编码 + `# -*- coding: utf-8 -*-`。
